# nfcxx's fixes to mrustc

Base: upstream `thepowersgang/mrustc` at `d85e86b` (PR #441), the commit nfcxx pins in
`scripts/setup-mrustc.sh` of take-cheeze/nfcxx. Each entry is a bug found while compiling Rust programs and crates
with mrustc, with a minimal reproduction. A fix is one commit on this branch; the status column says which.

Every fix changes mrustc's output, so the nfcxx rewrites in `scripts/mrustc-prep.rb` are checked against the new output
(the census in `docs/notes/mrustc-frontend.md`, section 2) before the pin moves.

## Verification

- #1: the helper, old and fixed, compiled as C and checked against gcc's `unsigned __int128` multiply overflow flag on
  eight fixed cases and 200,000 random pairs. Old: 928 wrong (including `2^100 * 2^28`). Fixed: 0 wrong, and the product
  is right whenever no overflow is flagged. The compiler builds from this branch (`make`).
- #2: a sweep of `checked_mul` on literal operands, 873 cases over the boundary values of i8, u8, i16, u16, i32, u32 and
  i64, compared with rustc's output. Old compiler: 304 wrong. Fixed compiler: 0 wrong. The run-time path is unchanged.
- #3: the repro above compiled with rustc and printed `3`; the old compiler aborts with `No arm matched` and the fixed one
  prints `3`. `consume_item` had no case for `async`, so its default returned no match.
- #7: the repro prints `7` with rustc and the fixed compiler. `unsafe` blocks, `async {}` and `async move {}` are unchanged.
- #8: the repro prints `9` with rustc and the fixed compiler; the pinned compiler aborts with the TODO.
- #9: the `Pin<&mut Self>` repro prints the same as rustc with the fixed compiler.
- #4: the repro prints `done` as rustc does. Generic-constant tests: `Option<u8>::None` and `Option<u32>::Some(7)` in a generic impl print the same as rustc; a per-instantiation test (`u8` and `u64` instances of a `VTable` whose entries depend on `T`) prints the same; a generic `Cell<u8>` constant is not promoted (its `&'static` use is rejected by both compilers, and a non-static use prints the same). A generic constant of a `Drop` type in a non-static borrow still runs its drop (not promoted). With this change, `make LIBS` (the fork's std libraries, rustc 1.90.0) builds with no BUG or error lines.
- #10: the `async fn` repro (`async fn five() -> u32 { return 5; }` and `async fn checked(n) -> Result<..>` whose body is a `loop` with a `return`, run by a small `block_on`) prints the same as rustc with the fixed compiler; the old compiler aborts with the error. Bug 12 is only reproduced (its repro is accepted by rustc).
- #6: the repro above prints `Unit` with rustc and the fixed compiler; the old compiler aborts with `No arm matched`. The std libraries (`make LIBS`, 1.90) build with no BUG lines. libc 0.2.191 is not yet compiled: its next error is bug 13.
- #4 remainder: `const N: Option<T> = None; &H::<T>::N` (`get::<u8>()` and `get::<String>()`) gave `Lifetime bound '#local0: 'static failed` before the change and prints `None` twice after, as rustc does. `&None::<String>`, a `&None` of a generic enum with a drop type, and the drop-clobber case (a promoted `&None::<D>` read after the stack is reused) print what rustc prints both before and after. Negative cases, base and fixed compilers: a generic `Cell` constant (`Some(Cell::new(0))`) prints `1 1` as rustc does; a generic constant that builds a `Drop` type (`(PhantomData<T>, D(1))`) prints `in f`, `drop D(1)`, `end`. The fixed compiler builds the 1.90 std libraries (`make LIBS`) with no BUG or error lines.
- #5 remainder: not reached (see the row). Valid probes (rustc and mrustc both accept and run the same): a trait's provided const through a generic call with a float literal argument (`fn show<X: T>(_: X) -> i32 { X::N } show(2.0)`), a `[u8; 4]` array length, `<f32 as G<_>>::N` for a generic trait with one impl per type, and a generic `P::<X>::K`. Invalid probes that leave `Self` unbound: rustc rejects them (E0283 for `<_>::N`, `<_ as T>::N`, `P::<_>::K`; E0493 for a drop of a `const fn` argument), and mrustc aborts in typeck with `Spare rules left after typecheck stabilised` (`expr_cs.cpp`) for the E0283 forms, so the primitive abort is not reached from them either.
- #13: the repro prints `1`, as rustc does, with the fixed compiler; the old compiler aborts with `Cannot find component 0 of crate::linux::can`. A glob cycle asks for the same module under a different name (`linux` while resolving `j1939`), which the guard keyed on the module alone rejected.
- #12: the repro prints `done`, as rustc does, with the fixed compiler; the old compiler aborts with `None of erased lifetime lifetime bounds [...]`. The erased return type of an `async fn` was built in the pre-2024 mode, which captured only lifetimes named in its bounds (none), so the future was `'static`.
- #14: the repro prints `1 2 4` with the fixed compiler; with bug 13 fixed alone it aborts with `Cannot find component 1 of crate::new::linux::can`. The probe of `pub use linux::can::j1939::*` ran `new::linux` while that lookup was already on the guard stack. The unbound component inside the probe is not an error, and the probe finds nothing. The negative cases (`crate::nothere::*`, `crate::nothere::sub::*`, `crate::nothere::sub::X`, `crate::k::q::*`) are rejected as before. libc 0.2.191 builds to an rlib with this branch (`mrustc --crate-type rlib --edition=2021`, with `feature="std"` and a subset of the cfgs its build script sets; not the full set).
- #15: `fn main() { let _ = make(5u8); println!("ok"); }` with `async fn make<T>(x: T) -> T { x }` prints `ok` with the fixed compiler; the old one aborts. With a small `block_on`, `make(41u32) + 1` prints `42`, and `Option<T>`/tuple outputs print the expected values. A non-generic `async fn f(x: String) -> String` aborts at run time on the old compiler too (not changed here).
- #16: the repro prints `7` with the fixed compiler; the old compiler reports `No applicable methods for {Pin<&mut dyn Tr>}.poll_it`. tokio's `reusable_box.rs:119` is the same call.
